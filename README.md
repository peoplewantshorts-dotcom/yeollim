# 열림 (yeollim)

2026년 장애인 분야 해커톤 「장애 플러스 기술」 · 분야 1 디지털 포용 · 팀 **바닥부터**

사용자의 신체 조건과 매물의 접근성 정보를 대조해, **방문 전에** 갈 수 있는 집인지 판정해 주는 앱.

## 지금 되는 것

사용자 → 중개사 → 사용자로 한 바퀴가 실제로 돌아간다.

| 화면 | 경로 | 하는 일 |
| --- | --- | --- |
| 시작 | `app/index.tsx` | 브랜드 · 소리로 듣기 |
| 나는 누구인가요 | `app/role.tsx` | 당사자 / 중개사 |
| 내 몸 프로필 | `app/user/profile.tsx` | 유형별 문항 분기, 5문항 + 있으면 좋은 것 |
| 내 요구서 | `app/user/request.tsx` | '꼭 필요'만 뽑아 카드 1장 생성 → 전송 |
| 맞는 집 | `app/user/matches.tsx` | 3단계 판정 카드 (+ 확인 전 보류 표시) |
| 받은 의뢰 | `app/agent/index.tsx` | 요구서 요약 + 매물별 확인 진행률 |
| 확인 질문 | `app/agent/checklist.tsx` | 요구서 → 질문 자동 변환, 있음/없음/**모름** 탭 |
| 통화 분석 | `app/agent/call.tsx` | 발화에서 답 추출 + 근거 구간 병기, 확신 없으면 비움 |

## 설계에서 양보하지 않는 것

- **판정은 규칙 기반**(`src/domain/matching.ts`)만으로 정해진다. AI는 데이터를 채우는 보조일 뿐, 판정에 개입하지 않는다.
- **모르는 것은 채우지 않는다.** 확신도 0.7 미만이면 비우고 '확인 필요'로 남긴다. 임대인의 "모르겠네요"는 '없음'이 아니다.
- **확인 안 된 집을 초록으로 칠하지 않는다.** '꼭 필요' 중 미확인이 남으면 '아직 확인 중이에요'로 보류한다. 앱이 확인하지 않은 안전을 단정하지 않기 위한 것이다.
- **색만으로 알리지 않는다.** 판정은 색 + 글자 + 도형(● ▲ ■ ○) + 음성 네 겹으로 전달한다. 흑백으로 뽑아도 구분된다.
- **손 떨림을 오류로 처리하지 않는다.** 550ms 안의 연속 입력은 한 번의 의도로 센다 (`useSteadyPress`).
- **말로 답해도 앱이 대신 고르지 않는다.** 인식 결과는 언제나 "이렇게 들었어요, 맞나요?"로 확인을 받은 뒤에만 저장된다. 못 알아들었을 때 사용자를 탓하지 않고 다시 말하기와 손으로 고르기를 나란히 준다.
- **최소 터치 영역 48dp**, 시간 제한 없음, 모든 인터랙티브 요소에 이름과 상태(`aria-checked`) 부여.
- **최종 판단 주체는 사용자 본인.** 중개사와 보호자는 확인을 도울 뿐이다.

## 실행

```bash
npm start            # 개발 서버
npm run test:engine  # 판정·통화분석·질문변환
npm run test:voice   # 말로 답하기 매칭
npm run typecheck
```

**주의: 이제 Expo Go 로는 못 띄웁니다.** 음성 인식이 네이티브 모듈이라 개발 빌드가 필요합니다.

```bash
npx eas build -p android --profile development
```

한 번 만들어 폰에 깔아두면 그다음부터는 `npm start` 로 코드만 바로바로 반영됩니다.
빌드를 다시 해야 하는 때는 네이티브 모듈을 새로 넣거나 app.json 의 plugins 를 고칠 때뿐입니다.

## 목소리

기기에 깔린 음성합성은 한국어를 사람처럼 읽지 못한다. 그런데 이 앱이 읽어주는 문장은
대부분 미리 정해져 있다 — 질문, 선택지, 안내문. 그래서 그 문장들은 **좋은 목소리로
미리 만들어 앱에 넣어 두고 그대로 튼다.** 매물 이름이나 치수처럼 그때그때 달라지는
문장만 기기 음성합성으로 읽는다.

```bash
npm run voice:lines   # 읽어주는 고정 문장을 전부 모은다 (현재 82개 · 1,186자)
npm run voice:make    # 음성 파일을 만들고 목록을 갱신한다
```

`voice:make` 는 아래 둘 중 하나가 있으면 된다.

```bash
GOOGLE_TTS_KEY=...                     # 구글. 무료 한도가 넉넉하다
CLOVA_ID=... CLOVA_SECRET=...          # 네이버 클로바. 한국어가 제일 자연스럽다
```

목소리를 바꾸려면 `TTS_VOICE` 를 준다 (구글 `ko-KR-Chirp3-HD-Leda` / 클로바 `nara` 가 기본).
문항을 고친 뒤에는 두 명령을 다시 돌려야 새 문장의 음성이 생긴다.
만들지 못한 문장은 조용히 기기 음성합성으로 넘어가므로 앱이 멈추지는 않는다.

## APK

로컬에 JDK / Android SDK 가 없으므로 클라우드 빌드로 뽑는다.

```bash
npx eas build -p android --profile preview
```

`preview` 프로필은 `.apk` 를 만든다(기본 `production` 은 `.aab` 라 제출 형식과 다르다).
제출 파일명은 `바닥부터_열림_디지털포용.apk`.

## 아직 안 된 것

- **통화 녹음 → 글자**: 녹음 파일을 텍스트로 옮기는 단계는 아직이다. 지금은 `src/domain/seed.ts` 의 대본을 입력으로 쓴다. 추출 로직(`analyzeTranscript`)은 그 텍스트를 실제로 읽고 판단하므로 녹음이 실물로 바뀌어도 그대로 동작한다.
- **말로 답하기**: 매칭 엔진은 33개 테스트로 검증했고, 마이크가 막혔을 때 손으로 돌아가는 길도 확인했다. 다만 **실제로 말해서 고르는 경로는 실기기에서 아직 안 해봤다**.
- **기기 간 동기화**: 사용자와 중개사가 각자의 폰을 쓰려면 서버가 필요하다. 지금은 한 기기 안에서 두 역할이 오간다.
- 시각장애 사용자 대응(화면 낭독 전면 검수)은 제안서대로 다음 단계.
